# Doz: แนวทางหน้าจอและระบบหลังบ้าน

## เป้าหมายหน้าจอ

ผู้ใช้ควรเห็นสถานะล่าสุดและสิ่งที่ควรทำก่อนดูตัวเลขเซนเซอร์ หน้าสถานะจึงเรียงเป็น: การเชื่อมต่อ → สถานะความเสี่ยงพร้อมคำแนะนำ → ภาพรวมการแจ้งเตือนและแบตเตอรี่ → ค่าจากเซนเซอร์ → คำอธิบายผล

สีสถานะใช้ความหมายเดียวกันทั้งการ์ดหลักและป้าย: Safe สีเขียว, Watch สีเหลือง, Warning สีส้ม, Emergency สีแดง, Unknown สีเทา ข้อความระดับต้องปรากฏเสมอ เพื่อไม่ให้ต้องตีความด้วยสีอย่างเดียว

## ความหมายของข้อมูล

- เมื่อไม่ได้เชื่อมอุปกรณ์ ข้อมูลตัวอย่างต้องมีป้าย “สาธิต” ชัดเจน
- เมื่อ BLE เชื่อมแล้วแต่ยังไม่มี packet ให้แสดงการรอข้อมูล ไม่ใช้ค่าจาก demo แทน
- Red/IR เป็นค่า ADC ดิบ ไม่ใช่ HR หรือ SpO₂
- Unknown หมายถึงยังวิเคราะห์ไม่ได้ ไม่ใช่ Safe

## หลังบ้าน

API `/overview` ส่งจำนวน event ตามระดับล่าสุดไม่เกิน 100 รายการของบัญชีที่ผ่านการยืนยันตัวตน ใช้ gate เดียวกับ `/sensor` และ `/alert` และไม่ส่งค่าชีวสัญญาณดิบใน response เหมาะสำหรับหน้าแสดงภาพรวมในอนาคต

ก่อนใช้งานจริงต้องตั้งค่า Auth และ storage ที่คงทนให้ครบ เปิด health-data sync ตามนโยบายข้อมูลส่วนบุคคล และทดสอบการเชื่อมต่ออุปกรณ์จริง แอปบน Render ยังต้องมี static web deployment และค่า Supabase สำหรับเว็บ

## สิ่งที่ปรับแล้ว

- หน้าหลักแยกภาพรวมออกจากค่าเซนเซอร์ และสถานะหลักใช้สีตามระดับที่แสดงจริง
- หน้าประวัติข้อมูลปรับจำนวนคอลัมน์ตามความกว้างหน้าจอ
- หน้าประวัติ alert แสดงสถานะว่างพร้อมข้อความไทย/อังกฤษ
- หน้าอุปกรณ์แสดงขั้นเปิดอุปกรณ์ เชื่อม BLE และรอ packet แยกกัน
- API `/overview` ตรวจสิทธิ์และสรุปจำนวนระดับโดยไม่คืนค่าดิบ

## งานก่อนเปิดใช้งานจริง

1. ทดลองกับผู้ใช้บนมือถือจริง รวมข้อความภาษาไทยยาวและการขยายขนาดตัวอักษร
2. ตั้งค่า Supabase Auth, storage ถาวร และนโยบายความยินยอมก่อนเปิด cloud sync
3. เชื่อม `/overview` เข้ากับหน้าแสดงประวัติเมื่อ cloud sync พร้อม และทดสอบการโหลด ล้มเหลว และข้อมูลว่าง
4. Deploy static web service บน Render ด้วยค่าตั้ง public ที่ถูกต้อง แล้วทดสอบ auth และ BLE บนอุปกรณ์จริง
